# Техническое задание для проекта Loandepot

## Главное:

- Необходимо реализовать web-приложение по макету: [Figma](https://www.figma.com/design/bmHwagvWgxG2hRF5TN7qZJJG/loandepot?node-id=0-6223&p=f&t=yZPttDh0MbRnahzr-0)
- На данный момент это главная страница и страница с модулями
- Сама бойлерплейтная информация пока может быть сгенерирована, дальше она заменится на реальную (название модулей, описание, тэги...)
- Видео так же пока могут быть любыми
- Десктопная версия работает в режиме **постраничного перелистывания**, мобильная в целях оптимизации не содержит таких переходов. Там лишь блоки один за другим. Мобильный макет не предусмотрен, так что сильно в дизайн можно не вдаваться
  _Примечание: сейчас это называют "работа в условиях неопределенности", но по факту часто или дизайнер не придумал, или не было заплачено_
- Каждая страница в десктопном режиме занимает 100% высоты, контент **адекватно** умещается в ней
- Данные должны располагаться в базе данных и на сервере, и отдаваться в формате REST API

---

### Используемые технологии:

- Фреймворк/библиотека React / Next.js / Vue / Nuxt на выбор как основа клиентской части
- Серверная часть, при необходимости, на Express.js
- Нереляционная база данных на выбор
- Для создания монорепозитория использовать Turborepo, по необходимости
- Использование готовых компонентов библиотек разрешается, если это уместно
- Для форм использовать schema-валидатор Zod
- Система контроля версий Git со следующим Git-flow:
  - Ветки main, develop и ${feature}
  - Каждая отдельная фича идет в ветку со своим названием
- В папке docs разместить данный файл ТЗ. Генерация документации желательна, но на усмотрение
- Клиентскую часть дополнить анимациями интерактивных элементов на свой вкус

---

### Серверная часть:

- Схемы и модели данных формировать по существующим в макете данным
- Использовать только формат REST API
- ORM можно использовать любую

### Технические нюансы каждой страницы/секции

#### Общее:

- В левом навигационном блоке клик по логотипу ведет на первую секцию, при клике на стрелку перемещаемся на следующую страницу
- Такие кнопки как "schedule an appoitment" или "Get (free) access" пока ничего не делают, там будет перенаправление на сервис бронирования
- Иконка с 9ю точками в правом верхнем углу - это часть кнопки бронирования
- При клике на воспроизведение видео открывается модальное окно с видео. Любого формата и из любого API

#### Hero section

- Базовый слайдер работает как обычно
- Только на активном слайде появляется описание и стрелка-ссылка
- При клике на стрелку идет переход к странице модулей **с нужным номером**
- При клике на "плюсик" идет переход на страницу модулей с первым модулем
- Количество модулей соответствует количеству секций на другой странице
  _Примечание: в идеале, чтобы данные и тут и там подтягивались с одного места в БД. Чтобы можно было централизовано руководить ими_

#### The difference

- Интерактивный элемент показывает новые "карточки"
- Начальное состояние обеих - это "Click to show". Данные статичны
- Когда нажаты все кнопки, появляется заголовок и описание для видео + кнопка посмотреть. Сам блок с фото превращается в блок с видео и принимает меньшие размеры (смотри макет)

#### Explore

- На кнопке "вперед" у слайдера стоит таймер для автопереключения
- По возможности реализовать компонент "слайд" под слайдами
- В слайдах только у активного слайда появляется заголовок и описание
- Левый слайд при переключении вперед исчезает. При переключении назад появляется

#### Join

- Стандартная форма со стандартной валидацией. В выбор города можно закинуть несколько примеров

#### How are you

- Слайдер с увеличенным по размеру активным элементом

#### Schedule

- В форме стандартная валидация
- В инпуте с выбором даты/времени желательно использовать готовое решение

#### Страница модулей

- Большинство правил теже: переключение секций, кнопки и тп
- Второе видео открывается только после просмотра первого
  _Необязательно, но если сможешь - будет прикольно_
- Кнопка "How are you showing up?" Пока ничего не делает, это букинг
- Кнопка "Скачать пдф" качает пдф файл
- Дополнительная навигация внизу страницы
- Бейджики подставляются динамически, на основании данных с БД
- **Все данные по модулям, в том числе и ссылки на файлы, должны быть в базе данных**

#### Остальные требования

- Оценка в Lighthouse на мобильных и десктоп устройствах не должна быть меньше 75 в Perfomance и 90 в остальных категориях
